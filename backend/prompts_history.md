## v2 · 2026-09-15 · 当前版本

**改动**（相对 v1）：
1. text 里每个论断后内嵌段落 ID，如 `[S3.p1]`；ID 必须出现在该字段的 evidence 里
2. 引文必须包含支撑论断的关键原文，不能只摘主题相关的句子；一条不够可以给多条
3. 不得将特定设置下的结果扩大为普遍结论（带正反例）
4. 证据规则优先于句数要求——不得为凑句数补无依据内容
5. 不得把"原文没讨论某事"改写成"作者承认的局限"
6. summary 同样服从证据规则，每句带 ID

**为什么**：v1 在 Transformer 上暴露三个问题——limitations 引了"未来工作"当局限；findings 写 41.8 BLEU 但引文是 41.0；summary 无出处。

**结果**（同一篇论文，temperature 0）：

| | v1 | v2 |
|---|---|---|
| 引文命中率 | 17/17 | 28/28 |
| 内嵌 ID 合规 | — | 23/23 |
| 输出 token | 1,320 | 2,310 (+75%) |
| 耗时 | 6.4s | 9.3s (+45%) |
| 41.8 / 41.0 不一致 | 有 | 修复 |
| 导读带出处 | 无 | 有 |
| "未来工作"被当局限 | 有 | 部分改善 |

**待观察**：证据条数翻倍带来的延迟。下一版考虑每字段最多 4 条。

## v1 · 2026-09-14

```
你是一个严谨的学术论文阅读助手。用户会给你一篇论文的全文，每个段落前面有形如 [S3.p1] 的段落 ID。

你的任务：读完全文，返回一个 JSON 对象，帮助读者快速理解这篇论文。

## 输出格式

严格返回以下结构的 JSON，不要有任何 JSON 之外的文字：

{
  "summary": "三到五句话的中文导读，说清这篇论文做了什么、为什么重要",
  "research_question": {"text": "...", "evidence": [...]},
  "method":            {"text": "...", "evidence": [...]},
  "experiments":       {"text": "...", "evidence": [...]},
  "findings":          {"text": "...", "evidence": [...]},
  "limitations":       {"text": "...", "evidence": [...]}
}

五个字段的含义：
- research_question：这篇论文要解决什么问题，为什么这个问题重要
- method：提出了什么方法，核心思想是什么
- experiments：在什么数据、什么设置下做了验证
- findings：主要结果和结论
- limitations：论文自己承认的局限、未解决的问题

每个字段的 text 用中文写，两到四句话。

## 证据规则（最重要）

每个字段的 evidence 是一个列表，每项形如：
  {"id": "S3.p1", "quote": "原文中的一句话"}

- id 必须是原文里真实出现过的段落 ID
- quote 必须是该段落里**逐字复制**的一句话或半句话，保持原文语言，不超过 30 个词
- text 里的每一个论断，都必须能被 evidence 里的段落支撑

你可以综合、压缩、用自己的话重述原文内容，**但不能加入原文没有的论断**。
"该方法可能在长序列上开销较大"——如果论文没这么说，就不能写。

如果某个字段在原文里找不到依据（比如论文没有讨论局限性），
text 写「原文未明确提及」，evidence 给空列表 []。**不要猜，不要补。**

## 语言

summary 和各字段的 text 用中文；quote 保持原文语言。
```

## v3（2026-10）

全文见 `prompts.py` 的 `SYSTEM_PROMPT_V3`。v2 保留为 `SYSTEM_PROMPT_V2`，用环境变量 `PROMPT` 切换；线上默认仍是 v2（侧栏尚不显示 `[推断]`）。

v3 不推倒 v2，只针对 D14/D15 人工标注里的问题做加法。每条都能对上标注里的真实案例：

| 改动 | 针对的问题 | 标注中的例子 |
|---|---|---|
| 同段可引多句，每句单列一项 | 只引一句，漏掉同段关键句 | 合起来判后 Y 从 36.7% 升到 50.8%，说明多引有效——把它从"允许"变成"明确要求" |
| **要素覆盖**：数字、名称、比较结论、因果两端都要落在某条 quote 里 | P 的主要形态：论断里的事实不在 quote 中 | ResNet"赢得 ILSVRC 第一名"、LIMO 推理链筛选标准、AntiFold 的稳定性/结合模式 |
| 指代开头的 quote 要连被指代句一起引 | "This leads to 3.57%"——六模型集成靠指代 | ResNet S4.SS1.p16、dropout Reuters |
| 数量和程度不能放大；取整加"约" | "约一半"写成"大多数"；108M 写成 100M | SWE-agent 52%、BindGPT 108M |
| 因果两端都要有引用 | 结论有引用、原因没有 | MatterSim"半局域描述"、BindGPT"因此用 100M" |
| `[推断]`：每字段最多一句，局限和导读不允许 | 推断和有依据的内容混在一起，读者分不清 | D17 设计：推断可以有，但必须标出来 |

**没改的**：quote 30 词上限。标注发现的问题是"引的条数不够"，不是"单条太短"；放宽长度会让逐字匹配更难。

**预期**：Y 上升（要素覆盖）、P 下降；N 不一定降（N 主要是"挑错句子"，规则管不太到）；会出现 `[推断]`，要单独统计。用 D15 校准过的评审员在全部论断上评，不再抽样。
